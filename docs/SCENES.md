# 장면(scene) 규격 — 원고 작성자용

영상 원고(`VideoScript`)의 `chapters[].scenes[]` 에 쓰는 장면 종류(`kind`)와 `params`, 그리고 **내레이션 문장이 화면 단계에 어떻게 배분되는지**를 정리한 표다.
기준은 실제 렌더러(`studio/video/scenes/*.py`)다. 이 문서와 렌더러가 다르면 렌더러가 맞고, 이 문서를 고친다.
원고 JSON 전체 형식은 `docs/SCRIPT_FORMAT.md`, 콘텐츠 규칙은 `docs/CONTENT_GUIDE.md`.

## 0. 공통 규칙

### 시간이 흐르는 방식
- 장면 하나 = **단계(step)** 의 연속. 기본은 `narration` 의 문장 i → 단계 i. 단계가 바뀔 때 새 요소가 나타나거나(올라오기·밀려오기·튀어나오기·닦아내기) 기존 요소가 움직이고·흐려지고·모양이 바뀐다.
- 문장 하나 = TTS 클립 길이 + 0.25초. 장면 앞에는 0.35초 전환(첫 장면은 0.15초)이 붙는다.
- 문장이 **요소보다 적으면** 요소를 고르게 묶어 한 문장에 여러 개가 시차를 두고 나온다. 문장이 **요소보다 많으면** 남는 문장은 마지막 단계에 머문다(제목이 있는 장면은 첫 문장을 제목만 보여 주는 도입으로 쓴다).
- 문장이 모자라 비는 단계는 **조용히 보여 준다(hold)**: 아래 표의 "문장 없을 때" 시간만큼.
- `hold_seconds`(최대 180): 내레이션이 끝난 뒤 화면을 더 보여 주는 시간. 단 `quiz`·`sequence`·`flow(hidden)` 은 `countdown` 을 따로 주지 않으면 `hold_seconds` 를 **생각할 시간(카운트다운)** 으로 쓴다.
- 쇼츠는 59초 이하(넘으면 경고). 화면 자막은 문장마다 자동으로 굽는다(`voice` 장면만 예외).

### 모든 장면이 받는 params

| params | 뜻 |
|---|---|
| `variant` | 레이아웃 변형 0~2 강제. 없으면 영상 ID + 장면 id 해시로 고르고, 바로 앞 장면과 같은 kind·변형이면 다음 변형으로 바꾼다 |
| `transition` | `"xfade"`(앞 장면에서 겹쳐 바뀜) 또는 `"cut"`. 없으면 해시로 고른다 |
| `kicker` | 장면 위 작은 머리말. 없으면 챕터 제목, `""` 이면 없음. 세로 자리를 아끼려고 `ox`(hook 있을 때)·`table_blank`·`diff`·`ranking`·`flow`+`hidden`(title 있을 때)·`relations`·`calc` 는 자동 머리말을 생략한다(직접 쓴 `kicker` 는 보인다) |
| `basis` | **근거 배지**(§1). 모든 kind 가 받는다 |
| `bank_id` | 문제은행 문항 ID — 문자열 하나 또는 목록(빈칸표처럼 여러 문항이면 `["Q-…", "Q-…"]`). 화면에는 안 나온다. `plan validate` 가 문항이 있는지·verified 인지·장면 정답과 같은지 검사하고(리허설 `STUDIO_DRY_RUN=1` 에서만 draft 를 경고로 허용), 실제 `weekly ship` 이 콘텐츠별로 `bank mark-used` 를 대신 부른다 |

### 글자 크기·넘침
- 세로(1080×1920) 본문 최소 56px, 가로 최소 48px. 들어가지 않으면 글자를 줄이고, 최소 크기로도 안 들어가면(말줄임 `…`·잘림·영역 넘침·근거 배지와 겹침)
  **렌더 오류**로 그 편을 인코딩 전에 멈춘다(`render video` 종료 코드 1, `[오류] <ID>: … 화면에 글이 다 들어가지 않습니다` 아래에 장면·글 목록).
  잘린 지문·보기가 그대로 발행되지 않게 하려는 것이다 — 목록의 글을 짧게 고쳐 다시 렌더한다.
  원인을 미리보기로 보고 싶을 때만 `render video --preview --allow-overflow`(경고로 낮춤, `weekly build` 는 쓰지 않는다).
- 자리가 모자라면 렌더러가 먼저 스스로 줄인다: 퀴즈 보기 상자 여백, 계산 막대 두께·줄 간격, 타임라인 사건 간격(가로 화면은 한 줄 배치로 바꿈).
- 세로 화면은 위 14%·아래 22% 가 플랫폼 UI 자리다. 장면은 진행 막대 아래 ~ 자막 위 사이에만 그린다.

## 1. 근거 배지 `params.basis` (모든 kind)

| 쓰는 값 | 화면 |
|---|---|
| `{"law_name": "공인중개사법", "article": "제33조 제1항", "effective_date": "2026-01-01"}` | `[공인중개사법 제33조 제1항 · 2026.1.1 시행 기준]` |
| `{"case_no": "2019다12345", "decided_at": "2020-03-12"}` | `[대법원 2019다12345 · 2020.3.12 선고]` (사건 부호로 법원 추정. 헌법재판소는 `결정`. `court` 로 직접 지정 가능) |
| `{"kind": "calc", "note": "가액 = 순영업소득 ÷ 환원이율"}` | `[계산 · 가액 = 순영업소득 ÷ 환원이율]` |
| `"[공인중개사법 제10조 · 2026.1.1 시행 기준]"` (문제은행 `badges[0]`) | 그대로 |
| `"표준국어대사전"` | `[표준국어대사전]` |
| 위 값들의 목록 | 줄마다 하나(최대 3개) |

- 형식은 문제은행 `Basis.badge()` 와 같다. 날짜는 `2026-01-01`·`2026.1.1`·`20260101` 모두 된다.
- 시행일·선고일이 없으면(사전형에 `effective_date`·`decided_at` 이 없거나, 문자열이 `제○조`·사건번호를 가리키는데 `· YYYY.M.D 시행 기준`·`선고` 가 없으면)
  `plan validate` 가 **오류**로 막는다(시행일 없는 근거는 쓰지 않는다 — CONTENT_GUIDE §7). 렌더러는 `시행일 미상`으로 그리고 경고한다.
- 위치: 본문 영역 맨 아래 띠. 세로에서는 **자막 바로 위**(아래 안전영역·자막과 겹치지 않음). 본문은 배지 높이만큼 위로 줄어든다.
- 한 줄에 안 들어가면: 글자 94%·88% → 법제처 약칭(예: 국토의 계획 및 이용에 관한 법률 → 국토계획법) → `·` 뒤에서 두 줄. 약칭은 화면에서만 쓰고 원고·문제은행에는 정식 명칭을 쓴다.
- 나타나는 때: 기존 장면은 단계 0(조금 늦게 밀려 들어옴). `quiz` 는 해설 상자 안(같은 형식 — 배지마다 한 줄, 길면 약칭, 그래도 길면 `·` 뒤에서 두 줄). 시험 장면은 아래 표의 "근거 배지" 칸.

## 2. 시험 대비 장면 (studio/video/scenes/exam.py)

### `ox` — 함정 OX

| params | 필수 | 설명 |
|---|---|---|
| `statement` | ● | 지문(`**강조**` 가능). 길이는 아래 "세로 쇼츠 길이" 표를 따른다 |
| `answer` | ● | `true`(O·맞는 지문) / `false`(X·틀린 지문). `"O"`·`"X"` 도 된다 |
| `wrong_word` | | X 지문에서 틀린 말(지문에 그대로 있어야 함) → 취소선 |
| `right_word` | | X: 끼워 넣을 정답 말 / O: 형광펜으로 강조할 말 |
| `timer` | | 생각할 시간(초, 기본 3, 0이면 없음). 막대·숫자가 줄고 째깍 소리 |
| `hook` | | 첫 문장 훅 글(지문 위 큰 글씨) |
| `explanation` | | 짧은 해설(공개 뒤 타이머·결과 자리에 상자로). 세로 쇼츠는 한 줄 — 18자 이하 |
| `label` | | 지문 이름표(기본 `지문`) |
| `reveal_line` | | 공개할 문장 번호(아래 자동 규칙 대신) |

단계: `[훅] → 지문 → 타이머 → 공개 → 교정/강조 → 해설·근거`

| 문장 | 화면 |
|---|---|
| 공개 문장 R | `reveal_line` → `정답`이 처음 나오는 문장(1번 이후) → hook 이 있고 N≥3 이면 2, 아니면 1 → N≤1 이면 없음 |
| 0 ~ R-1 | hook 이 있고 R≥2 이면 문장 0 = 훅, 1~R-1 = 지문 카드. 아니면 모두 지문 카드(훅은 같이) |
| (타이머) | `timer` 초 동안 내레이션 없이 카운트다운 |
| R | O/X 공개: 카드 테두리가 정답색(O 초록·X 빨강)으로, 변형별 O/X 표시 |
| R+1 | X + `wrong_word`: 그 줄부터 아래가 밀려 자리가 열리고 → 틀린 말 취소선·흐림 → `right_word` 말풍선이 위에 들어옴(약 1.5초). O + `right_word`: 형광펜 |
| R+2 ~ | 해설·근거 배지 |
| 문장 없을 때 | 공개 1.6초, 교정 애니메이션+1초, 해설·근거는 읽는 시간 |

변형: 0 카드 오른쪽 위 도장 + `정답 X · 틀린 지문` 알약 / 1 O·X 큰 단추 두 개(정답만 채우고 다른 쪽 흐림) / 2 진한 지문 카드 + 고리 타이머 → 같은 자리 큰 도장. 가로는 왼쪽 60% 지문, 오른쪽 공개 영역.

세로 쇼츠 길이(변형 3벌 모두에서 말줄임 없이 들어가는 길이 — 2026-W42 리허설에서 잰 값, 교정 `wrong_word`·`right_word` 포함):

| 조건 | 지문 `statement` | 해설 `explanation` |
|---|---|---|
| `hook` 있음 | 30자 안팎(근거 배지가 한 줄이면 35자까지) | 한 줄, 18자 이하 |
| `hook` 없음 | 50자 안팎 | 한 줄, 18자 이하 |
| 가로(롱폼) | 70자 안팎 | 2~3줄 |

근거 배지가 두 줄(긴 법령명 + 항·호)이면 지문 자리가 그만큼 준다. 넘치면 렌더가 멈추고 어느 글을 줄일지 알려 준다.

```json
{"id": "s1", "kind": "ox",
 "narration": ["대항력, 당일일까요 다음 날일까요?", "지문을 읽고 3초 안에 판단해 보세요.", "정답은 X입니다.", "당일이 아니라 다음 날부터 생깁니다.", "주택임대차보호법 제3조 제1항입니다."],
 "params": {"hook": "대항력, **당일**일까 다음 날일까?",
            "statement": "주택임대차의 대항력은 주택의 인도와 주민등록을 마친 당일부터 제3자에게 효력이 생긴다.",
            "answer": false, "wrong_word": "당일부터", "right_word": "다음 날부터", "timer": 3,
            "basis": {"law_name": "주택임대차보호법", "article": "제3조 제1항", "effective_date": "<시행일>"}}}
```

### `table_blank` — 숫자 빈칸표

| params | 필수 | 설명 |
|---|---|---|
| `columns` | ● | 머리칸 2~5개 |
| `rows` | ● | `[[칸, ...], ...]` 1~10행(세로는 6행 안팎 권장). 칸 수 = columns |
| `blanks` | | 빈칸 `[[행, 열], ...]`(0부터). **적은 순서대로** 채운다 |
| `highlight_rows` | | 헷갈리는 행 번호(0부터, 보통 2개). 마지막에 색 강조, 나머지 행은 흐려짐 |
| `title` | | 표 제목(가로는 왼쪽 단) |
| `think` | | 빈칸마다 채우기 전 생각할 초(기본 0). 그동안 그 `?` 가 깜박이고 째깍 |

| 문장 | 화면 |
|---|---|
| 처음 N−B−H 문장(최소 1, 최대 행 수) | 머리행 + 행이 차례로 등장. 빈칸은 `?` 칩 |
| 다음 B 문장 | 문장마다 빈칸 하나가 채워짐(칩이 사라지고 값이 튀어나옴) |
| 다음 1문장(H=1, highlight_rows 있을 때) | 헷갈리는 행 색 강조 |
| 문장 없을 때 | 빈칸 1.6초씩, 강조 2.2초 |
| 근거 배지 | 단계 0 |

B = 빈칸 수, H = 강조 여부(0/1). 예: 문장 5 = 행 2 + 빈칸 2 + 강조 1. 변형: 0 진한 머리행 + 줄무늬 / 1 행마다 카드 / 2 밑줄 머리행 + 첫 칸 이름표.

### `relations` — 판례 관계도

| params | 필수 | 설명 |
|---|---|---|
| `nodes` | ● | `[{"id", "label", "sub"?, "at"?}]` 2~6개. `label` 은 짧게(갑·을·병), `sub` 는 역할(매도인). `at: [0~1, 0~1]` 로 위치 지정(없으면 자동: 2개 좌우, 3개 삼각형, 4개 네모…) |
| `edges` | ● | `[{"from", "to", "label"?, "dashed"?}]`. 같은 두 노드 사이 화살표는 나란히 벌어진다. `dashed: true` 는 점선(가등기 등) |
| `question` | ● | 질문 카드 |
| `conclusion` | ● | 결론 카드(`**강조**`) |
| `highlight` | | 결론에서 강조할 노드 id 목록 |

| 문장 N | 화면 |
|---|---|
| N ≥ E+3 | 문장 0 = 인물만, 1..E = 화살표 하나씩, 다음 = 질문, 다음 = 결론 |
| 3 ≤ N < E+3 | 인물은 첫 화살표와 같이, 화살표 E개를 처음 N−2 문장에 나눔 → 질문 → 결론 |
| N ≤ 2 | 인물·화살표 모두 문장 0, 질문 1, 결론은 조용히 |
| 근거 배지 | 결론 단계(판례: `{case_no, decided_at}`) |

세로에서 질문·결론 카드가 함께 안 들어가면 결론이 질문 자리를 대신한다. 이름표는 노드·다른 이름표와 겹치지 않는 자리를 찾아 놓는다. 변형: 0 흰 카드 노드 / 1 둥근 인물 노드(역할은 아래) / 2 진한 알약 노드.

### `calc` — 계산 단계

| params | 필수 | 설명 |
|---|---|---|
| `conditions` | ● | 조건 글 목록 |
| `steps` | ● | 수식 줄 목록(6줄 이하, `**강조**`) |
| `answer` | ● | 정답 숫자(막대 길이용) |
| `answer_text` | | 정답 표시 글(예: `200만 원`. 없으면 숫자+unit) |
| `unit` | | 단위 |
| `distractors` | | 흔한 오답 `[{"label", "value", "text"?}]` 3개 이하. 없으면 막대 대신 큰 정답 카드 |
| `answer_label` | | 정답 막대 이름표(기본 `정답`) |

| 문장 N | 화면 |
|---|---|
| N ≥ K+2 | 문장 0 = 조건 카드, 1..K = 수식 한 줄씩(앞 줄은 흐려짐), K+1 = 정답 vs 오답 막대 |
| N < K+2 | 수식 K줄을 1..N−2 문장에 묶음 → 막대 |
| 문장 없을 때 | 수식 1.6초, 막대 2.6초 |
| 근거 배지 | 막대 단계 |

세로에서 셋이 다 안 들어가면 막대 단계에 조건 카드를 접고 수식을 위로 올린다. 가로는 왼쪽 조건·수식, 오른쪽 막대. 변형: 0 흰 조건 카드 + 번호 원 / 1 옅은 조건 카드 + 네모 번호 / 2 진한 조건 카드 + 계단식 수식.

### `diff` — 개정 전후 비교

| params | 필수 | 설명 |
|---|---|---|
| `before` | ● | `{"label"?: "개정 전", "text"}` 구법(바뀐 부분 앞뒤만 짧게) |
| `after` | ● | `{"label"?: "개정 후", "text"}` 신법 |
| `changed` | | 바뀐 글 조각 목록 — 구법에서는 회색, 신법에서는 강조색 형광펜 |
| `effective_date` | | 신법 시행일(없으면 타임라인 없이 경고) |
| `title` | | 제목 |
| `exam_date` | | 타임라인의 시험일(기본 `channel.yaml` 의 `exam.next_exam_date`) |
| `show_exam` | | `false` 면 시험일 표시 안 함 |

| 문장 N | 화면 |
|---|---|
| 4 이상 | 0 구법 → 1 신법(화살표) → 2 바뀐 부분 색 강조 → 3 시행일 타임라인(시행일·`제37회 시험 2026.10.31` 표지) |
| 3 | 0 구법+신법 → 1 강조 → 2 타임라인 |
| 2 이하 | 0 구법+신법 → 1 강조+타임라인(문장 없으면 조용히) |
| 근거 배지 | 단계 0 |

가로는 좌우, 세로는 위아래(조문이 길어 안 들어가면 세로도 좌우로). 타임라인은 날짜 비율대로 표지를 놓고, 이름표가 겹치면 시험일을 선 아래로 내린다. 변형: 0 흰 카드 두 장 / 1 색 머리띠 카드 / 2 구법 흐린 카드 + 신법 진한 테두리.

### `ranking` — 오답 랭킹(앱 데이터)

| params | 필수 | 설명 |
|---|---|---|
| `items` | ● | `[{"label", "value", "note"?}]` **1위부터** 2~7개(5개 권장) |
| `unit` | | 기본 `%` |
| `focus_index` | | 확대 해설할 항목(0부터, 기본 0 = 1위) |
| `title` | | 제목 |
| `note` | | 집계 출처·기간·표본(예: `함정노트 앱 · 10.1~10.7 · 풀이 3,214회`). 없으면 경고 — 근거 없는 통계 금지 |
| `explanation` | | 확대 카드 해설(항목의 `note` 가 먼저) |

| 문장 | 화면 |
|---|---|
| 처음 N−1 문장(최대 항목 수) | 막대가 **낮은 순위부터** 나온다(문장이 모자라면 묶음) |
| 그다음 문장(남는 문장도 여기 머묾) | focus 항목 확대 카드(순위·값·지문·해설), 나머지 막대는 흐려짐. 문장이 없으면 읽는 시간만큼 조용히 |
| 근거 배지 | 단계 0 |

변형: 0 막대 / 1 막대 + 1위 값은 막대 안 / 2 행마다 카드.

### `flow` + `hidden` — 절차 흐름도 빈칸(기존 `flow` 확장)

| params | 설명 |
|---|---|
| `steps` | 단계 글 목록(5~7개) |
| `hidden` | `?` 로 가릴 단계 번호(0부터, 숫자 하나 또는 목록) |
| `title` | 제목(있으면 자동 머리말 생략) |
| `reveal_line` | 공개 문장 번호. 없으면 `정답`·`답은`이 처음 나오는 문장(1번 이후) → 마지막 문장 |
| `countdown` | 공개 전 생각할 초. 없으면 `hold_seconds`, 그것도 없으면 3초. 그동안 `?` 가 깜박이고 째깍 |

단계: 공개 전 문장들에 단계 상자가 차례로(숨긴 단계는 `?` 칩) → 생각할 시간 → 공개 문장부터 칩이 사라지고 그 상자에 고리 + 근거 배지(문장이 하나뿐이면 2초 동안 조용히 공개). `hidden` 이 없으면 기존 `flow` 와 똑같다.

## 3. 기존 장면

| kind | params | 문장 → 단계 |
|---|---|---|
| `title` | `title`, `subtitle?` | 제목 0, 부제 min(1, 마지막) |
| `chapter` | `title`, `index?` | 모두 0(시차) |
| `text` | `heading?`, `body` | 본문을 문단(`\n`)·문장으로 나눠 문장마다 하나. 제목이 있고 문장이 더 많으면 첫 문장은 제목만. 지난 문단은 흐려짐 |
| `bullets` | `heading?`, `items[]` | 문장마다 항목 하나(제목 규칙 같음). 현재 항목 강조 |
| `case` | `title?`, `body`, `label?`(기본 `사례`), `reconstructed?`(true → `재구성 사례` 표시) | `text` 와 같음 |
| `quote` | `text`, `source?` | 인용 0, 출처 min(1, 마지막) |
| `quiz` | `question`, `choices[2~5]`, `answer`(**0부터**), `explanation`, `basis?`, `countdown?`, `reveal_line?` | 문제 → (보기) → 카운트다운(`countdown` → `hold_seconds` → 5초, 경고) → 공개 R(`reveal_line` → `정답` 문장 → 1) → 해설. 근거는 해설 상자 안 |
| `compare` | `left_title`, `right_title`, `rows[[왼, 오], ...]` | 행 하나씩(문장이 행보다 많으면 첫 문장은 머리만) |
| `sequence` | `items[]`(정답 순서), `shuffled?`, `sort_line?`, `countdown?` | 섞인 카드 → (생각할 시간) → 문장 S(`sort_line` → `정답` 문장 → 1)에서 정렬 → 이후 문장마다 카드 하나씩 강조 |
| `timeline` | `events[{label, text}]`, `title?` | 사건 하나씩(선이 이어짐). 가로 화면에서 세로 목록이 근거 배지에 밀려 넘치면 한 줄(가로) 배치로 바꾼다 |
| `flow` | `steps[]`, `title?`, `hidden?`(§2) | 단계 하나씩(상자 + 화살표) |
| `bars` | `items[{label, value}]`, `unit?`, `title?` | 막대 하나씩(자라남), 값 표시 |
| `image` | `path`(저장소 기준), `caption?` | 그림 0, 설명 min(1, 마지막) |
| `voice` | `audio`(사람 녹음), `heading?`, `image?`, `label?`, `cues?`(문장별 시작 초) | TTS 대신 녹음. narration 은 큰 자막으로만(화면 자막 굽지 않음). 문장 = 단계 |
| `cta` | `headline`, `body?`, `button?` | 헤드라인 0, 본문 1, 버튼 2(문장 수에 맞춰 당김) |
| `outro` | `headline?` | 모두 0 |

## 4. 카드뉴스 시험 장(참고)

`CardSlide.kind` 는 그대로 두고 `params` 로 레이아웃이 바뀐다(`studio/cardnews/exam.py`).

| 장 | 쓰는 법 | 화면 |
|---|---|---|
| OX 퀴즈 | `{"kind": "quiz", "title": "<지문>", "params": {"choices": ["O", "X"], "answer": "X", "basis": {...}}}` | 큰 지문 + O·X 큰 단추 + 근거 배지 |
| OX 정답 | 바로 다음 `{"kind": "answer", "title"?, "body": "<해설>", "params": {"basis": {...}}}` | 큰 O/X 도장(또는 정답 단추만 채움) + 해설 + 근거 |
| 숫자 표 | `{"kind": "body", "title": "<표 제목>", "body": "<표 아래 메모>", "params": {"table": {"columns": [...], "rows": [[...]], "highlight_rows": [3, 4]}, "basis": {...}}}` | 표(2~4칸, 8행 이하) + 메모 + 근거 |

- OX 장의 `answer` 는 `"O"`·`"X"`(권장) 또는 `true`/`false`. **숫자 `1` 은 거부한다** — 0부터(X)와 1부터(O) 해석이 갈려 정답이 뒤집힐 수 있어서. (보통 퀴즈 장의 숫자 정답은 지금처럼 1부터.)
- 카드의 근거에 시행일·선고일이 없으면 렌더가 **오류**로 멈춘다(이미지에는 경고를 남길 자리가 없어서).
- `params.basis` 는 위 세 장뿐 아니라 표 없는 body·list·보통 퀴즈·정답 장에도 아래쪽 배지로 그린다(본문 자리를 배지 높이만큼 줄임).
  표지(cover)·마무리(cta) 장에 쓰면 오류 — 숫자·요건이 나오는 장으로 옮긴다.
